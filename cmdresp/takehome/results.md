### Interface

Small matrix-vector accelerator, prompt revision **3**, SHA-256 `c3f654a92c03042c11350fddceb0a1bf3a7497c86d81f7fb3275e6cca8429d23`. Observed cross-layer result: **126/126 scenarios PASS**. Sources: each scenario key in [python](accelerator/evidence/python_checks.json), [csim](accelerator/evidence/csim_checks.json), [cosim](accelerator/evidence/cosim_checks.json), [rtl](accelerator/evidence/rtl_checks.json).

One 32-bit input AXI-Stream and one 32-bit output AXI-Stream; AXI-Lite carries only control/status. Every header and nonempty payload is a separate TLAST-terminated burst. All byte-valid strobes are asserted.

| Command / response | 32-bit words | TLAST |
|---|---|---|
| CONFIG | `[1, tx_id, R, C]`, then R×C row-major elements | Header word 4; final matrix element |
| DATA | `[2, tx_id, C, 0]`, then C elements | Header word 4; final vector element |
| END | `[0, tx_id, 0, 0]` | Header word 4 |
| Successful DATA response | `[2, tx_id, R]`, then R signed 64-bit results | Header word 3; high word of final result |

Each sample is a signed int16 two’s-complement value sign-extended to 32 bits. Each result is serialized low 32 bits first, then high 32 bits. CONFIG and END have no response. Repeated uint32 IDs are echoed unchanged. Concrete serialized examples: [layout.json](accelerator/evidence/layout.json), keys `command_example`, `signed_input_example`, `response_example`; [layout.md](accelerator/layout.md).

All status registers are unsigned **32-bit**: `halted` at 0x10, `error` at 0x20, `tx_id` at 0x30; control at 0x00. Companion validity/interrupt registers are the standard HLS control interface. Status initializes to 0/0/0 at every activation and stays zero on normal completion. Generated address/width evidence: [synthesized_rtl/matvec_control_s_axi.v](accelerator/evidence/synthesized_rtl/matvec_control_s_axi.v), `Address Info` and `int_halted/int_error/int_tx_id` declarations.

| Error | Meaning |
|---|---|
| 1 | Early or missing header TLAST |
| 2 | Unknown opcode |
| 3 | DATA before CONFIG |
| 4 | Invalid dimensions, DATA length, or reserved argument |
| 5 | Early payload TLAST |
| 6 | Missing payload TLAST |

Validation priority is header framing → opcode → DATA configuration availability → arguments → payload framing. The first detected failure sets halted=1, error, and offending ID (zero when its header word has not arrived), then returns without draining. No response is emitted for a failed command; earlier responses remain complete. Temporary emptiness waits. END stops at its fourth word; errors stop at the detecting word, including at the **external** input handshake. No later word may be accepted through idle before another activation.

### Design


The scalar Python golden and C++ body multiply signed 16-bit operands into exact signed 32-bit products, sign-extend each into a signed 64-bit accumulator, and clear the accumulator per row/vector. The largest possible magnitude is 16×2³⁰=2³⁴. A row loop contains a pipelined dot-product loop. No rounding or saturation occurs.

The active matrix and a separate staging buffer each hold 256 int16 values; the vector buffer holds 16. CONFIG validates the entire staging payload before copying it and committing dimensions. DATA buffers and validates its entire payload before the first response word. Local configured state starts false at each activation. No errors remain to be detected during response emission, so every started output burst closes before any later command can fail.

The maintained [interface_codegen.py](accelerator/interface_codegen.py) extends Waveflow’s interface signature emitter before generation, reading `axis_register_modes` from [matvec.py](accelerator/matvec.py). It emits `register_mode=off` on s_in. The installed Waveflow package and generated files are never edited. Header/payload/command loops explicitly disable pipelining to prevent reads ahead of validation. Output registration remains enabled. Synthesis confirms unregistered input: [input_interface.json](accelerator/evidence/input_interface.json), `no_registered_input` and `binding_lines`; actual RTL handshake evidence is reported separately below. AMD defines the mode in [UG1399](https://docs.amd.com/r/2025.1-English/ug1399-vitis-hls/pragma-HLS-interface).

Wire encoding uses generated Waveflow schemas and array serializers. The installed int64 stream helper discards TLAST, so the body uses the generated array serializer followed by the supported stream word writer with explicit burst boundaries. This does not manually pack result bits. Sources: [kernel](accelerator/matvec_body_impl.tpp), [golden](accelerator/matvec.py), [protocol model](accelerator/protocol_model.py), [testbench](accelerator/matvec_tb.cpp). No Python timing model was built.

### Assumptions


- The supplied revision 3 prompt governs conflicts with the Waveflow frame: CONFIG state persists within an activation, all fields/status registers are 32-bit, errors follow the prompt's numbering, and no Python timing model is built. The user's request authorizes implementation and verification through completion.
- The available toolchain is Vitis HLS/Vivado 2026.1. The reference part (`xc7z020clg484-1`), requested 10 ns clock and default uncertainty are retained; no tool-version equality was required by the prompt.
- The specification does not assign errors to invalid TKEEP/TSTRB or non-sign-extended samples. Inputs obey the full-byte-strobe, sign-extended int16 host contract. Output byte strobes are checked explicitly in C and at RTL pins.
- AXI-Lite status offsets are determined by generated RTL. Each output register also has the standard HLS validity/control companion. Read statuses after completion; normal interrupt/control registers carry no computational parameters.
- A source that stops sending without TLAST causes an indefinite wait. Finite testbench timeouts are verification failures, never accelerator protocol error codes.
- Matrix atomicity is implemented with distinct staging and active arrays. After a failed CONFIG the activation terminates, so the uncommitted internal state is not externally observable; source inspection complements output tests for atomicity.
- All results are emitted only after complete DATA validation. No failure can occur during a started response; completed responses have already closed their bursts before a later command fails.
- Latency counts both boundary edges (`last-first+1`), as explicitly required. The throughput elapsed-cycle window also uses inclusive endpoints: N/(last result handshake-first vector handshake+1), with N=8 and initial CONFIG excluded. No throughput, II or resource threshold was supplied.
- Reset recovery means resetting the DUT and discarding the previous producer queue before the next activation. The pin testbench asserts reset for eight clock cycles after every protocol error. Successful activations restart without reset to test clearing configuration; new input is also presented during pre-start idle.
- The pin suite retains valid sentinels through at least 20 idle cycles after observing completion. Standard co-simulation's trimmed input replay is not used as evidence of physical stopping.
