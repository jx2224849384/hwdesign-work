## 1. Interface

One 32-bit input AXI-Stream and one 32-bit output AXI-Stream. AXI-Lite carries control/status only. Each header and nonempty payload is a separate TLAST-terminated burst.

| Message | Serialized 32-bit words | TLAST |
|---|---|---|
| CONFIG | `[1, tx_id, R, C]`, then `R*C` row-major samples | Header word 4; final sample |
| DATA | `[2, tx_id, C, 0]`, then `C` samples | Header word 4; final sample |
| END | `[0, tx_id, 0, 0]` | Word 4 |
| DATA response | `[2, tx_id, R]`, then results row by row, low 32 bits followed by high 32 bits | Header word 3; high word of last row |

Samples are sign-extended int16 values in signed 32-bit wire fields. Outputs are signed int64 two’s-complement, low word first. All serialization uses Waveflow schemas/array utilities. Concrete serialized examples: [layout.json](matvec/evidence/layout.json) (`command_example`, `signed_input_example`, `response_example`). CONFIG/END have no response. Failed commands emit nothing; earlier complete responses remain.

Status registers: `halted` (1 bit, offset 0x10), `error` (8 bits, 0x20), `tx_id` (32 bits, 0x30). Control is 0x00; generated control/interrupt and validity registers occupy the other documented offsets. All status clears at activation. Source: [generated AXI-Lite RTL](matvec/evidence/interface/matvec_control_s_axi.v), Address Info block.

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | Early/missing header TLAST |
| 2 | Unknown opcode |
| 3 | DATA before CONFIG |
| 4 | Invalid arguments |
| 5 | Early payload TLAST |
| 6 | Missing payload TLAST |

Validation order is header framing → opcode → DATA configuration availability → arguments → payload framing. Stop on the detecting beat, with no drain; malformed-header tx_id is zero until its word arrives. The implementation attempts to disable input AXIS registers via Tcl, but the generated pragma overrides it; physical read-ahead remains an Open Item. Temporary input emptiness stalls.

## 2. Design

The active matrix and staging matrix each hold at most 256 signed 16-bit elements. A 16-element vector buffer holds each complete DATA payload. CONFIG commits only after validation, replacing dimensions and matrix. DATA validates fully before emitting its header. A sequential row loop runs a pipelined dot-product loop; every product is exact signed 32-bit and is sign-extended into a signed 64-bit accumulator initialized to zero per row/vector. The worst absolute sum is at most 2^34. Matrix/configuration state persists only within an activation. No Python timing model was built.

Source: [kernel body](matvec/matvec_body_impl.tpp), [scalar golden](matvec/matvec.py), [beat protocol model](matvec/protocol_model.py). The original arithmetic architecture was retained; subsequent changes corrected framing and input read-ahead.

## 5. Assumptions

- The assignment is revision 2. Its explicit CONFIG protocol, four full-word header, validation order, and exclusion of a Python timing model override the reference frame's defaults.
- Every header field and transaction ID is unsigned 32-bit. IDs may repeat and need not be monotonic. Successful status is all zeros, regardless of the END transaction ID.
- Input sample serialization uses a signed 32-bit Waveflow field containing a value in -32768..32767, then narrows to signed 16-bit in the kernel. Non-sign-extended sample encodings are outside the host contract and are not assigned an error code.
- CONFIG has no reserved argument: both arguments are dimensions. DATA reserves arg1; END reserves both. DATA configuration availability takes precedence even when its length is zero or arg1 is nonzero.
- Early header TLAST terminates parsing on that beat. Locally zero-filled unreceived fields allow schema decoding without read-ahead. If only opcode arrived, status tx_id is zero; if the second word arrived, that ID is reported.
- A missing TLAST is detected on the prescribed final header/payload word. More words may already be queued; they remain unread. Fewer words without any TLAST cause a blocking wait, with no timeout or invented protocol error.
- CONFIG is staged separately and copied into the active matrix only after complete payload validation. Failed CONFIG returns immediately, so its old matrix is not externally observable afterward; atomicity is also established by the separate staging/commit code. Recovery starts unconfigured and must configure anew.
- Every DATA payload is fully buffered/validated before its response header. Rows are then computed and emitted sequentially. There are no remaining data-dependent error checks after response emission; every emitted burst is therefore complete.
- All full 32-bit stream byte lanes are valid. TKEEP/TSTRB are full on transmit; host-conforming inputs use full masks. These sidebands are not additional validation inputs; the specified comparison covers TDATA, TLAST, and status.
- Products are signed 32-bit; accumulation and results are signed 64-bit. The maximum absolute sum is at most 16*2^30=2^34, so signed 64-bit accumulation cannot overflow. No arithmetic truncation occurs in the product or sum.
- Initial architecture: one sequential row loop containing a pipelined dot-product loop (requested II=1), staging/commit loops requested II=1, and fixed maximum buffers. No performance-only redesign is performed after measurements.
- Latency uses elapsed clock periods from the first vector-input handshake to the last high-word result-output handshake (edge difference, without adding an inclusive cycle).
