- The assignment is revision 2. Its explicit CONFIG protocol, four full-word header, validation order, and exclusion of a Python timing model override the reference frame's defaults.
- Every header field and transaction ID is unsigned 32-bit. IDs may repeat and need not be monotonic. Successful status is all zeros, regardless of the END transaction ID.
- Input sample serialization uses a signed 32-bit Waveflow field containing a value in -32768..32767, then narrows to signed 16-bit in the kernel. Non-sign-extended sample encodings are outside the host contract and are not assigned an error code.
- CONFIG has no reserved argument: both arguments are dimensions. DATA reserves arg1; END reserves both. DATA configuration availability takes precedence even when its length is zero or arg1 is nonzero.
- Early header TLAST terminates parsing on that beat. Locally zero-filled unreceived fields allow schema decoding without read-ahead. If only opcode arrived, status tx_id is zero; if the second word arrived, that ID is reported.
- A missing TLAST is detected on the prescribed final header/payload word. More words may already be queued; they remain unread. Fewer words without any TLAST cause a blocking wait, with no timeout or invented protocol error.
- CONFIG is staged separately and copied into the active matrix only after complete payload validation. Failed CONFIG returns immediately, so its old matrix is not externally observable afterward; atomicity is also established by the separate staging/commit code. Recovery starts unconfigured and must configure anew.
- Every DATA payload is fully buffered/validated before its response header. Rows are then computed and emitted sequentially. There are no remaining data-dependent error checks after response emission; every emitted burst is therefore complete.
- All full 32-bit stream byte lanes are valid. TKEEP/TSTRB are full on transmit; host-conforming inputs use full masks. These sidebands are not additional validation inputs; the specified comparison covers TDATA, TLAST, and status.
- Products are signed 32-bit; accumulation and results are signed 64-bit. The maximum absolute sum is at most 16*2^30=2^34, so signed 64-bit accumulation cannot overflow. No arithmetic truncation occurs in the product or sum.
- Initial architecture: one sequential row loop containing a pipelined dot-product loop (requested II=1), staging/commit loops requested II=1, and fixed maximum buffers. No performance-only redesign is performed after measurements.
- Latency uses elapsed clock periods from the first vector-input handshake to the last high-word result-output handshake (edge difference, without adding an inclusive cycle). Throughput uses the seven completion intervals across eight consecutive 16x16 DATA commands in one activation; report (8-1)/(last_completion-first_completion) vectors/cycle. CONFIG and initial fill are excluded from that steady-sequence rate; a full-window rate is also recorded. No throughput, II, or resource limit was specified.
- Vitis HLS 2026.1 is the installed tool. The reference part xc7z020clg484-1, 10 ns requested clock, and default uncertainty are retained. Estimated synthesis timing is not post-route timing.
- Recovery uses a new activation and fresh stream objects after every error. Status references retain the previous values in the C++ testbench; the hardware clears status each activation. Sentinels are queued after every error and END. RTL evidence must independently establish input stopping points, not infer them from expected consumed counts.
- RTL co-simulation uses a single combined suite, rather than separate co-simulation invocations for individual cases. If a waveform replay is required to export VCD, the same combined elaborated testbench is replayed and recorded explicitly in Run History.
- The result report is `cmdresp/takehome/results.md`. Evidence is retained under `matvec/evidence/`; generated interfaces/serializers and synthesized RTL remain available in the project.
- The no-read-ahead requirement is interpreted at actual input AXI-Stream handshakes, including interface buffers. The requested `register_mode off` Tcl directive is present, but the generated top-level pragma takes precedence and synthesis retains both-mode input registers. This remains an unresolved mismatch, not an accepted relaxation of the contract.
- A supplemental pin-level co-simulation supplies full queues because Vitis's generated C/RTL adapter trims unread input from replay. It tests all 85 scenarios in one invocation, with no physical reset between passing cases (including error/recovery pairs), and observes status through AXI-Lite. One normal functional case deliberately inserts a four-cycle input gap; the performance case uses continuously asserted input VALID and output READY.
